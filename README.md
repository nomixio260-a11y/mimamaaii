# tinyai — リアルタイムに学んで進化する小型言語モデル

**Transformer 言語モデル (自前実装、依存は numpy のみ) が応答を生成し、会話のたびに即座に学習し、
自分で成長する** AI です。メモリ上限 (既定 256MB) の中で最大のモデルを自動選択し、
テキスト / Web / 公開データセット / 会話データを自分で収集して学び続けます。
numpy が無い環境では、検索と事実ストアによる応答に自動で切り替わります。

## ニューラル LM が主役

| 仕組み | 内容 |
|---|---|
| 応答 | 準備が整ったら (取り置き ppl が基準内)、**すべての応答を Transformer が生成**。検索と事実ストアは文脈 (RAG) を渡すだけ。`--symbolic` で従来の即答経路も併用、`--tools` で計算・日付などの道具を有効化 |
| リアルタイム学習 | **各ターンの直後にその対話で勾配更新** (再生バッファの少量を混ぜて忘却を防ぐ、数十〜数百 ms)。👍 は重み 3 で追加学習、👎 は **unlikelihood 損失** (−log(1−p)) でその答えを出しにくくする |
| 常時学習 | chat / serve 中も学習スレッドが回り続け、収集した文・会話・事実からの合成 QA を学ぶ。`train --hours` で数プロセスのデータ並列学習 |
| 成長 (進化) | 損失が停滞したら **関数を保ったまま層を追加** (新層の出力射影をゼロで初期化: Net2Net 型)。新しいテキストに頻出する未知の単位を**語彙に追加**し、埋め込みも拡張。復号パラメータ (温度・top-p・繰り返しペナルティ) は 👍 率で山登り |
| 規模 | プリセット small 1.2M / base 2.9M / large 6.4M / **xl 17M** (d=384, 8 層, 文脈 160)。`TINYAI_NEURAL=auto` (既定) はメモリ上限から選ぶ: 200MB→base, 512MB→large, 1GB→xl。成長で層は最大 12 まで |
| アーキテクチャ | RMSNorm・RoPE・SwiGLU・重み共有・KV キャッシュ・top-p・繰り返しペナルティ・コサイン学習率・系列パッキング。逆伝播は手書きで有限差分検査済み |
| 計算の節約 | 出力層 (語彙全体への射影 = 1 ステップの計算の約半分) は**損失に効く位置だけ**で計算する。負例や短い系列のパディングを飛ばすので、無効位置 32% の場合で出力層が 43% 速くなる |
| 平均重み (EMA) | 評価・生成・書き出しに使うが、**毎回 EMA と生の重みの取り置き ppl を比べ、悪ければ生の重みに切り替えて EMA を作り直す** (学習が速いと EMA が追いつかず品質が落ちるため) |
| 学習効率 | **損失マスク**: 会話系列の文脈・発話 (プロンプト部) は重み 0.2、応答部は 1.0 で学習し、同じ計算量で会話の質に勾配を集中させる。**優先再生**: 系列ごとに直近の損失を覚え、まだ覚えていない (損失の大きい) 系列を (損失)^0.6 に比例して多く出す (半分は一様: 忘却と過学習の両方を避ける)。**ドロップアウト** (残差ブロック出力、既定 0.1) で小データでの過学習を抑える。埋め込みの勾配は one-hot 行列積をやめ並べ替え + 区間和 (5 倍速)。データ並列 (4 プロセスで 3.5k → 11k トークン/秒) は**新しく集めた系列をワーカーへ同期**し、語彙進化・層追加は並列ワーカーを作り直してから形を変える |
| 訓練と本番の一致 | RAG の写し取り練習は、半分を**実際の検索結果を文脈にして**作る (残り半分はその文 + 隣 + 無関係な文)。本番と同じ条件で「検索結果の中から使う文を選ぶ」ことを学ぶ |
| 文脈への忠実性 | 生成時、**文脈 (検索した文) に現れるトークンの対数確率を持ち上げる** (既定 +1.0、👍/👎 の山登りで 0〜5 を調整)。指示語で始まる発話や検索が弱い時は 0.3 倍にして自由に話させる。学習が進むとこの細工はほぼ不要になる (実測: バイアス 0 で接地率 0.889、3.0 で 0.928) |
| 会話の記憶 | 学習も生成も**直前のやり取りを含めた多ターン形式** (`<bos>[<ctx> 検索文][<usr> 過去発話 <bot> 過去応答]… <usr> 今の発話 <bot>`)。損失は最後の応答だけに掛かり、過去のやり取りは文脈として弱く学ぶ。公開データセットの会話も 1 往復ずつではなく**流れごと**取り込む。ブラウザ版も同じ |
| 自由な会話 | 文脈への復号バイアスは**検索の確信度で加減する** (弱い検索なら 0.3 倍)。雑談にまで検索文を写して「検索結果の寄せ集め」になるのを防ぐ |
| 容量の進化 | 損失が停滞したら層を追加し、層が上限に達したら**中間次元を広げる** (Net2WiderNet: 単位を複製し出力側の重みを半分ずつに分けるので関数を保つ)。上限は初期 ff の 3 倍 |
| 考える応答 | ニューラル応答は 2 段階: **下書き** (検索文脈で候補生成) → **読み直し** (下書きに出た句で再検索し、質問だけでは引けなかった文を文脈に足してもう一度生成) → **検証** (接地率 + 自己対数確率 + 文末の整いで全候補を採点)。過程は `Brain.last_thought` に残り、Web UI の「いま何を考えたか」に表示される |
| データの価値評価 | 収集した各ページについて、学習前にニューラル LM の**驚き** (平均トークン損失 nat) を測ってソースの評価表に加える。2〜5 nat = 学ぶ価値が高い、1 nat 未満 = 既知、6 nat 超 = ジャンクや別言語。ソースの点数 = 成功率 × (収穫 + 新規性) × 価値 で、次に読む源を選ぶ |
| ブラウザ版 | `python -m tinyai export` で重みを **int8 (行ごとのスケール、4 分の 1 のサイズ、base で 3MB)** に書き出し、`web/` の JS エンジン (Transformer の順伝播・逆伝播・AdamW・KV キャッシュ・BM25 を依存なしで移植、numpy と logits・損失・勾配が一致) がブラウザの中で応答し、**会話 1 ターンごとに重みを更新**する。会話していない間も **常時学習** (3 秒ごとに知識文か会話を 1 系列学ぶ) で進化し続ける。応答は下書き → 読み直し → 検証の 2 段階。UI は思い出した知識、読み直しで足した知識、注意の地図、一語ごとの確信度と候補、候補の点数、進化の数値 (パラメータ・層・語彙・学習ステップ・損失曲線) を表示。学習内容は端末の IndexedDB に保存 |

```
python -m tinyai            # 対話 (裏で自動学習が回る)
```

## 特徴

| 機能 | 仕組み |
|---|---|
| 会話 | 抽出済みの事実で即答できる質問 (「XのYは？」「Xとは？」「Xはいつ？」) は事実から答える。次に BM25 検索メモリ + 意味ベクトル + 学習型リランカー、確信が持てない時は関連語でクエリを広げ、それでも駄目なら知識に接地した生成 |
| 意味ベクトル | Random Indexing による語の分散表現を空き時間に学習 (加算だけ、1 文 60µs)。意味的に近い語の検索、質問と文の意味類似によるリランクに使う。純 Python の「密ベクトル検索」 |
| 生成 | 知識文全体の接尾辞配列で「今の文脈に最も長く一致する箇所の続き」を使い (Infini-gram 方式、次数無制限)、n-gram と会話キャッシュ LM を補間。候補を 4 本生成して LM スコア + 知識との整合で最良を選ぶ (self-consistency) |
| 学習型リランカー | 👍/👎 と教えた答えから、検索候補の良さをロジスティック回帰でオンライン学習 (特徴量 12 個) |
| 事実の学習 | 文から「主語 – 関係 – 目的語」(定義 / 属性 / 場所 / 出来事) を抽出して記憶。「AのBのCは？」は事実を連鎖して答える (多段推論)。英日の属性名 (creator ↔ 作者、capital ↔ 首都) は相互に引ける。文書が消えれば事実も消える |
| 近似重複の排除 | 句と数値の集合が同じ文 (語順や記号だけ違う) は取り込み時点で弾く。重複学習のコストがゼロになる |
| リアルタイム学習 | 会話で分からない話題が出た瞬間に収集スレッドが起き、最優先で調べる。学習できたら次の返答に「さっき『X』を調べました: …」と添える。会話の関心プロファイルに探索が追従する |
| 記憶の整理 | 一定周期で、同じ事実を持つほぼ同じ文を統合し、使われない知識を減衰させ、関心を減衰させる (睡眠中の記憶整理に相当) |
| 選択的学習 | 各文に品質 (定義文・数値・話題語・長さ) を付け、メモリが 6 割を超えたら質の低い文は取り込まない |
| 質問理解 | 「とは / いつ / どこ / いくつ / 誰 / なぜ」の質問タイプを判定し、型に合う文 (年号・地名・数値・人物) をリランク |
| 文脈 | 「それはいつ？」「もっと詳しく」のような話題語の無い発話は、直前の話題や答えた文の続きで応える |
| 自動学習 | 文章・ファイル・URL・`inbox/` フォルダに置いたファイルを文単位で取り込み。重複文・ジャンク文 (表の断片、記号/数字だらけ) は最初から捨てる |
| 収集システム | ソースはプラグイン登録制。Wikipedia (Core API / Action API)、Wiktionary (語義)、Wikinews (鮮度)、Wikibooks、Wikidata (説明文)、DuckDuckGo、青空文庫 (日本語文学 1 万作品超)、Project Gutenberg (英語文学)、RSS/Atom フィード、Wikipedia ランダム記事、`sources.txt` のサイト、リンクのフロンティア。ソースごとに成功率・文の収穫・**新しい語の収穫 (新規性)**・遅延を記録し、健全な順に使う。URL 重複排除、robots.txt と 429 バックオフ、先読みワーカー (`TINYAI_WORKERS`) |
| 大量データ | Wikipedia の XML ダンプ (.xml.bz2、数 GB) をページ単位でストリーミング学習 (メモリ一定)。zip/gz/bz2/xz の書庫、ディレクトリ、`inbox/` に置いたダンプや書庫も自動取り込み |
| 知らないと言う | 主語を知らない・属性を知らない質問には「まだ知りません。調べておきます」と答え、別の属性で誤魔化さない (知っている事実があれば添える) |
| 多出典投票 | 同じ事実を複数の出典が述べていれば支持が増え、食い違えば「別の出典では…」と矛盾を可視化。近似重複で弾いた別出典の文も裏付けとして数える |
| 要約回答 | 「X について教えて」には、事実 + 出典の異なる関連文を句の重なりで重複除去して 2〜3 文にまとめる |
| コスト適応 | 自律ループは収穫が続けば間隔を 1/4 に縮め、空振りが続けば 4 倍まで伸ばす。学習パイプラインは段階ごとの所要時間を記録 (`/stats` の `timers_ms`) |
| 会話データの選別 | 応答が長すぎるもの (220 文字超) は句点の区切りで先頭の数文に切り詰めて学ぶ (小さなモデルは長文を覚えきれない)。収集は**第 1 言語を優先** (第 2 言語以降は重み 0.4) し、限られた容量を分散させない |
| 会話データ | 自分の会話 (👍 が付いた応答は重み 3 倍、👎 は除外)、Hugging Face の公開対話/指示データセット (`data/datasets.txt`、datasets-server API)、Stack Exchange の質問と採用回答、青空文庫の「」の応酬。個人情報らしい文字列は落とす |
| エージェント層 | ChatGPT 型の対話体験を担う層 (`agent.py`)。意図を見て道具を正確に使う: **計算** (安全な式評価、% や乗も)、**日付・時刻** (N 日後は何曜日)、**単位換算** (km↔マイル、kg↔ポンド、℃↔°F など)、**比較** (「A と B はどちらが高い」を事実の数値で判定、「A と B の違い」)、**列挙** (「X の例を 3 つ」を知識文から抽出)、**要約** (URL / 貼り付けた文章 / 直前の話題)、**その場で調査** (「調べて: X」で収集して学んでから答える、時間上限つき)、**利用者プロファイル** (「私の名前は◯◯」を記憶し「私の名前は？」に答える)。**書式指示** (箇条書きで / 一言で / N 文字以内) を答えに適用し、Web 由来の答えには**出典** (ホスト名) を添える |
| ニューラル LM | numpy があれば、**LLaMA 系のデコーダ専用 Transformer** (RMSNorm・RoPE・SwiGLU・重み共有・KV キャッシュ・top-p・繰り返しペナルティ・コサイン学習率・系列パッキング、全部自前実装) を、サブワード語彙 (頻度ベース WordPiece 風、6,000 語) で学習。プリセット small 1.2M / **base 2.9M (既定)** / large 6.4M パラメータ (`TINYAI_NEURAL`)。学習データは平文、会話 (`<usr>` 発話 `<bot>` 応答)、RAG 形式 (`<ctx>` 検索文 + 会話)、事実ストアから自動生成した合成 QA (記号処理系からの蒸留)。取り置き ppl が基準を満たすと **RAG 生成が応答の主経路** になり、検索の確信が高い時だけ知識文をそのまま返す。生成文は接地率・自然さ・文の整形で検査し、通らなければ検索応答に戻す |
| 探索戦略 | 調査キュー > 関心 / 好奇心 / 知識の薄い語 / 種 を UCB1 で選択 (収穫の多い戦略を優先) |
| 進化 | 自己評価 (取り置き文のパープレキシティ + 検索の自己テスト + 👍/👎 の再現率) を適応度とし、パラメータを変異させて改善した時だけ採用。変異幅は成功で広がり失敗で狭まる (適応) |
| フィードバック | `👍` で「その聞き方 → その答え」を索引に結び付け、`👎` の直後に書いた平叙文は正しい答えとして直前の質問に結び付ける。知識の信頼度と回答しきい値も調整 |
| 記憶の量 | 既定のメモリ上限は **500MB**、知識文の上限はメモリに比例 (1MB あたり 400 文 = 500MB で 20 万文)。モデルの大きさも上限から選ぶ: 200MB→base (2.9M), **450MB→large (6.5M, 文脈 256)**, 1GB→xl (17M, 文脈 320) |
| 学習データの配合 | 再生バッファの系列は種類 (平文 / 会話 / 写し取り / 合成 QA) を持ち、写し取りは 30%、合成 QA は 15% を上限にする。偏ると RAG 忠実性は上がるが自由な文生成が弱る (実測: 忠実性 0.31→0.82 と引き換えに文 ppl 17→21) |
| 自動評価 | 学習中に一定間隔 (既定 5 分) で自分を評価する: 取り置き文の PPL、**会話としての PPL** (応答部だけ)、**RAG 忠実性** (文脈の語をどれだけ使うか)、キーワード再現率。結果は学習ログに残り、ブラウザ版の「サーバーでの自動評価」曲線になる。`tools/eval.py --sweep` で復号バイアスの掃引、`--fail-on-regress` で前回比 5% 以上の悪化を検出して終了コード 1 (CI 用) |
| メモリ制限 | 推定サイズ + 実 RSS の 2 段監視。超えると低頻度 n-gram と古い/役に立たない知識から削除。OS の `RLIMIT_DATA` も設定 |
| 省メモリ表現 | 学習系列 (再生バッファ) は int32 配列で保持 (Python リストの 1/9)。n-gram の文脈は整数 1 個にパック (20bit × 最大 3 トークン)、後続が 1 種類だけの文脈と投稿が 1 件だけの索引語は辞書を作らず整数で保持。同じデータで実メモリが約半分 |
| 依存なし | Python 3.10+ の標準ライブラリのみ。保存ファイルは gzip pickle 1 個 |

## 使い方

```bash
# 対話 (Web 探索スレッドが裏で走る)。終了時に自動保存
python -m tinyai chat
python -m tinyai chat --offline        # Web 探索なし
python -m tinyai chat --memory 128     # 上限 128MB

# 1 問だけ
python -m tinyai ask 日本の首都は？

# 学習: ファイル / ディレクトリ / URL / 話題
python -m tinyai learn notes.txt docs/ https://example.com/page topic:量子コンピュータ

# 大量データ: Wikipedia ダンプ (bz2 のまま、ページ単位でストリーミング) / 書庫
python -m tinyai learn dump:jawiki-latest-pages-articles.xml.bz2 --max-pages 20000
python -m tinyai learn corpus.zip texts.tar.gz   # zip/gz/bz2/xz の中のテキスト

# 自律学習ループだけを前面で回す (Ctrl+C で停止、10 サイクル or 1 時間で自動停止)
python -m tinyai evolve --cycles 10
python -m tinyai evolve --seconds 3600 --interval 30

# ニューラル LM (Transformer) を前面で学習する (numpy が必要: pip install numpy)
python -m tinyai train --steps 2000 --seconds 600          # 手元の知識と会話で
python -m tinyai train --hours 3 --size large              # 収集システムからデータを流し込みながら長時間
TINYAI_NEURAL=small python -m tinyai chat                  # 小さいモデルで裏学習 (低スペック向け)

# 学習しながら、その学習中のモデルと会話する (学習は止まらない)
python -m tinyai train --hours 4 --workers 4 --serve 8799
curl -s -X POST -d '{"text":"機械学習とは？"}' http://127.0.0.1:8799/ask   # 応答 + 思考過程 + 学習の状況

# ブラウザ版の書き出し (web/ と同じ場所に置いて静的配信する)
python -m tinyai export --out web/dist --log train.log
cp web/index.html web/engine.js web/worker.js web/dist/ && python -m http.server -d web/dist 8080
node web/validate.js web/dist         # JS 移植と numpy の一致検査 (トークナイザ・logits・損失・勾配)

# 状態 (世代・適応度・メモリ・ニューラル LM・会話データなど)
python -m tinyai stats

# HTTP API + 簡易 Web UI (http://127.0.0.1:8765/)
python -m tinyai serve
curl -X POST localhost:8765/ask   -d '{"text":"こんにちは"}'
curl -X POST localhost:8765/learn -d '{"text":"覚えさせたい文章。","source":"api"}'
curl localhost:8765/stats
```

### 会話中のコマンド

| 入力 | 動作 |
|---|---|
| `覚えて: 文章` / `remember: text` | その文をそのまま記憶 (優先度高) |
| `調べて: 話題` / `search: topic` | 次のサイクルでその話題を Web 検索 |
| `👍` / `👎` | 直前の答えを評価 (`👎` の直後に正しい文を書くとそれを覚えて質問に結び付ける) |
| `調べて: X` | オンラインならその場で収集して学び、答える。オフラインなら次のサイクルで調べる |
| `12×34は？` `3日後は何曜日？` `5kmはマイルで？` `AとBはどちらが高い？` `Xの例を3つ挙げて` `要約して: …` `私の名前は◯◯` | 道具で正確に答える (エージェント層) |
| `…を箇条書きで` `…を一言で` `…を50文字以内で` | 書式の指示 |
| `もっと詳しく` / `続けて` | 直前に答えた文の続きを同じ出典から返す |
| `/news` | 裏で調べ終えた話題の一覧 (HTTP では `/notices`) |
| `/stats` `/save` `/evolve` `/quit` | 状態表示 / 保存 / 進化を 1 回試す / 終了 |

### 完全自動で学ばせる

* **フォルダ投入**: `~/.tinyai/inbox/` に `.txt` `.md` `.html` `.csv` `.json` を置くと自動で取り込み、`learned/` に移動します。
* **サイト巡回**: `~/.tinyai/sources.txt` に URL を 1 行ずつ書くと、同一ドメイン内のリンクをたどって定期的に読みます。
* **フィード**: `~/.tinyai/feeds.txt` (または同梱の `data/feeds.txt`) の RSS/Atom を 30 分ごとに読み、新着記事を取り込みます。関心の高い記事は本文まで読みます。
* **公開データセット**: `data/datasets.txt` (または `~/.tinyai/datasets.txt`) に `dataset<TAB>config<TAB>split<TAB>形式` を書くと、Hugging Face datasets-server から順に読みます。既定は oasst1-21k-ja (Apache-2.0)、databricks-dolly-15k-ja / dolly-15k (CC BY-SA 3.0)。ライセンスは各データセットのページで確認してください。
* **話題の種**: `data/topics.txt` の話題から出発し、読んだ文の中の語へ好奇心で広がっていきます。

## 仕組み

```
ユーザー発話 ─┬─ コマンド? (覚えて/調べて/👍/👎/もっと詳しく)
             └─ 語に分解 ─ 関心プロファイル更新 ─ 話題語が無ければ前の話題を補う
                  ├─ 事実ストア (XのYは? / Xとは? / Xはいつ?) → 即答 (fact)
                  ├─ 知識ベース検索 (BM25 + 情報量重み + 動的ストップ語 + 品質) ─ 低確信なら関連語で拡張
                  ├─ 質問タイプ判定 (定義/いつ/どこ/いくつ/誰/なぜ) でリランク
                  ├─ 確信度 ≥ しきい値 → 回答 (recall) / 中程度 → 「たぶん…」(guess) + 調査キュー (→ 収集スレッドを即起動)
                  ├─ 言語モデル生成 (KN n-gram、見つかった知識の語を優先) (generate)
                  └─ 裏で調べ終えた話題があれば一言添える

収集システム (collector, 先読みスレッド):  フィード → フロンティア (リンク優先度) → 話題検索 (健全なソース順) → ready キュー
自律ループ (evolver):  inbox 取込 → 調査キューがあれば同期で即収集 / 無ければ ready から消費 → 学習 (文 + 事実 + LM)
                     → 数サイクルに 1 回 進化 (変異 & 自己評価) → 定期的に整理 (consolidate) → メモリ制御 → 保存
```

学習の流れは文単位で「知識ベース (重複・ジャンク・低品質を弾く) → 事実抽出 → 言語モデル」の順で、
意味ベクトルと接尾辞配列は「後回しの学習」として空き時間 (自律ループの各サイクル、整理時、応答の合間に数文) に取り込みます。
文の品質は `sentence_quality()`、事実抽出は `facts.py` の軽量パターン (1 文あたり数マイクロ秒) で行います。

**進化するパラメータ**: n-gram 使用次数、ディスカウント、BM25 の `k1` / `b`、句一致ボーナス、
クエリ拡張の重み、リランクの重み。回答しきい値は 👍/👎 でオンラインに動きます。
適応度が上がった変異だけが採用され、変異幅は成功で 1.5 倍・失敗で 0.9 倍に適応します。
👍/👎 と教えた答えは `qa_log` に残り、「今のパラメータでその答えを再現できるか」も適応度に入るので、
進化は評価指標だけでなく実際の会話の満足度に向かいます。

**学習コストの削減**:

* 知識ベースが受け付けなかった文 (重複・ジャンク) は言語モデルにも入れない。文ごとの語の分解は 1 回だけ。
* 関連語 (分布的な意味の近さ) は学習時には何も計算せず、必要になった時に転置索引から共起を数える (ゼロコスト学習)。
* 大きなファイルは 100KB ずつ流し込み、一時メモリを増やさない。
* 探索戦略の収穫量を記録し、成果の出ない戦略には Web アクセスを費やさない。

### ニューラル LM の実測 (numpy 2.4、CPU 4 コア、共有環境)

| プリセット | パラメータ (語彙 6,000) | 学習速度 (1 プロセス) | データ並列 (3〜4 プロセス) |
|---|---|---|---|
| small (d=128, 2 層) | 1.19M | 約 6,400 トークン/秒 | – |
| base (d=192, 4 層) | 2.92M | 約 3,800 トークン/秒 | 約 7,500〜9,000 トークン/秒 |
| large (d=256, 6 層) | 6.36M | 約 1,800 トークン/秒 | 約 4,500 トークン/秒 (推定) |

学習は **データ並列** (`neural_parallel.py`): CPU コアごとにプロセスを fork し、各プロセスが別のミニバッチの勾配を
共有メモリに書き、親が平均して AdamW を適用します (パラメータも共有メモリなのでコピー無し)。要素ごとの演算が
1 スレッドの numpy では、BLAS の多スレッド化 (1.4 倍) よりプロセス並列 (4 コアで 2.6 倍) の方が効きます。
`train --workers N` / `TINYAI_NEURAL_WORKERS`。生成は候補 n 本を 1 回の順伝播でまとめて進める (1 本ずつの約 2 倍)。

base を日本語 Wikipedia 3 記事 (79k サブワードトークン、合成 QA・抽出練習込み) で 5 分 (3 プロセス、491 ステップ、226 万トークン) 学習した結果:
損失 8.3 → 0.84、取り置き ppl 4.7 (前版: 6 分で ppl 7.3)。RAG 形式の生成例 (質問 → 検索文を文脈に生成):

```
機械学習とは？     → 機械学習とは、データから規則性を学び取ることで、明示的にプログラムしなくても判断や予測ができるようにする手法です。
統計学とは？       → 統計学とは、母集団と標本、そこに存在する確率分布に着目した方法論です。
宇宙について教えて → 宇宙太陽光発電は、宇宙空間での太陽光発電と無線による送電を組み合わせたシステムです。
```

この規模のデータでは記憶に近く、知らない話題を聞くと文脈の語を継ぎ合わせた文を作ります (接地率・自然さの検査で弾かれ、
検索応答に戻ります)。数百万〜数千万トークン (青空文庫・公開データセット・ダンプ) を `train --hours` で流すと汎化し始めます。
勾配の正しさは有限差分 (相対誤差 10⁻⁷ 台) と KV キャッシュの一致 (10⁻⁸) をテストで確認しています。
評価セットの刷新で見つかった不具合 (英語文がジャンク扱いで落ちていた、短い文が近似重複で落ちていた、
別の属性で答えていた、👍👎 が数件の段階でリランカーが効いていた) はすべて修正済みです。

実 Web での 5 サイクル (Wikipedia、間隔 1 秒) では 2,000 文と 21 件の事実を学習し、RSS 31MB → 45MB でした。

```bash
python tools/bench.py corpus.txt --memory 256
```

**メモリ制御**: 言語モデルは「エントリ数 × 推定コスト」、知識は「文字数と語数」で
サイズを推定し、予算 (上限 × 0.85 − インタプリタ基礎分) の 55% / 35% に収めます。
実 RSS が上限の 85% を超えたら予算そのものを 20% 締めて削り直します。

## 常に学習し続ける

「学習の完了」は存在しない。どのモードでも学習は止まらない:

* `chat` / `serve`: 収集スレッド (Evolver) が Web・公開データセット・会話データを集めて学び、学習スレッド (NeuralTrainer) が空き時間に Transformer を更新し続ける。会話のたびにそのターンで勾配更新
* `train --hours N`: 1 分ごとに 1 バッチ収集しながらデータ並列で学習 (新しい系列は即座にワーカーへ同期)。N 時間で止まるのはコマンドであって学習ではなく、次回は続きから再開する。
  `--serve PORT` を付けると**学習を続けたまま**会話 API が開き、いま学習中の重みでそのまま話せる (会話したターンもその場で学習される)
* ブラウザ版: 会話ごとの更新に加えて常時学習 (3 秒ごとに 1 系列) が走り、重みは端末に保存される

## 制限

* 形態素解析器も埋め込みも使わない極小構成なので、「賢さ」は蓄えた文の検索と
  n-gram 生成の範囲です。数百 MB の知識ベースでも、深い推論はできません。
* 極端に小さい上限 (64MB など) で大量の文章を一気に学習させると、Python が解放済みメモリを OS に返さないため、ピーク RSS が上限を 1〜2 割超えることがあります。既定の 256MB では十分な余裕があります。
* Web の検索エンジンや API はレート制限や bot 対策で失敗することがあります。
  失敗は記録して次のサイクルで別の話題に進みます (ループは止まりません)。
